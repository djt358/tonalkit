# Promises register

Every promise we make to volunteers, in [`CONSENT.md`](CONSENT.md), [`GUIDE.md`](GUIDE.md) and
[`copy.json`](copy.json), with the mechanism that keeps it and the test that fails if it breaks.
A promise with no mechanism doesn't go in the text.

How to read the status marks:

- `(built)`: it is in the repository now. `(built, as policy)`: it is written down and reviewed, not tested.
- `P4 (built)`, `C0 (built)`, `E1 (built)`: that task built it on its own branch (`s05/p4`, `s05/c0`,
  `s05/e1`); it arrives with the merge, and so do the files named with it.
- `P4 (pending)`, `P5 (pending)`: that task has not built it yet.
- `DJ (operational)`: no code can keep it; it is DJ's own routine. Read these twice.

`harness/tests/test_kit_promises.py` checks that every quotation below appears word for word in
the file it names, that every "never" in the consent has a row, and that the files named as
mechanisms exist (those that arrive with a branch are checked once it is merged). Change the
wording of a promise and the test tells you to change this table.

## Open items

Not built yet, by task:

- **P4 (its fix round 1):** a content-security policy with no outbound connections, and the test that
  every request goes to the page's own origin; the test that the microphone isn't requested before
  "I agree"; "Send again" and "Delete from this phone" (R77); "Finish and send what I have";
  `consent.declined`; the stop screen for in-app browsers (R84); a test that the page has no text
  field.
- **P5:** `tkh purge`; intake rejecting extra fields and accepting partial sessions; purge covering
  everything intake writes for a session, and marking outputs stale.
- **No owner yet:** `tkh provenance` accepts a pack with no `[[source]]` (it reads as unfitted), so a
  calibration fitted on volunteers is recorded only if its manifest says so. Requiring fitted packs
  to list their sources is what would make "used only to test and tune" and the stale marking
  checkable.

DJ's routine, which no code keeps:

- Only DJ can open the private workspace and the data root.
- The code is the key: a deletion request arrives as a code. After a purge, delete the original zip
  from wherever it arrived, and any copy in the private workspace.
- Read each report before it is committed: no per-speaker rows in the public repository.
- Change the wording of `CONSENT.md` only with a new version line (`v2`), since every bundle
  records the version its speaker saw.

Gaps found while writing this register:

- `scripts/check-no-audio.sh` blocks audio file types but not `.zip`, and a volunteer bundle is a
  zip of WAV files. R75 decided to add `zip` to the script and to `.gitignore`; neither is done.
- Nothing scans tracked files for session codes or speaker ids. Reports are the likely place one
  would slip in.
- "Never identify you", "never clone your voice" outside the harness, and "settings can't recreate
  your voice" are policy, with no automated test.
- No test removes `consent` from a bundle to see it refused; the model simply has no default for it.
- GitHub, which hosts the page, can see that the page was opened (never the recordings). The consent
  doesn't say so.
- The private workspace's provider has its own rules for how long it keeps what it holds. The
  consent says who can open the workspace, not how long the provider retains it.
- Safari may clear a site's saved data after a long time unused. The "within a few days" in
  `pause.body` is a safe guess, to check on a phone.
